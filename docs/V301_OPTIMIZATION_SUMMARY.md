## 主要改进点

### 1. 标题和描述更具体（参考v234/v287模式）

**第一版优化**:
```ruby
self.title = '给李四预订深圳运动健身度假酒店（6天后入住，住4晚）'
self.description = '李四是健身爱好者，想订深圳的运动健身度假，要健身房和游泳池'
```

**用户反馈**: 描述太笼统，需要更具体

**最终版本（参考v234/v287）**:
```ruby
self.title = '李四6天后要去深圳健身训练，需要预订配备专业健身房和游泳池的酒店住4晚'
self.description = '李四要去深圳健身训练，需要配备专业健身房和游泳池的酒店'
```

**关键改进**:
- 从"运动健身度假"（笼统） → "健身训练"（具体）
- 从"健身房"（普通） → "专业健身房"（强调专业性）
- 采用v234的具体场景模式："李四6天后要去...需要..."而非"给李四预订..."
- 强调设施的专业性和目的性（健身训练）

**改进理由**: 
- v234模式："张三3天后要去杭州出差，追求品质体验" → 场景+目的
- v287模式："健身养生酒店" → 强调具体功能
- v301采用："李四6天后要去深圳健身训练" → 场景明确，目的具体

### 2. 任务描述结构化（requirements hash）

**优化前（扁平结构）**:
```ruby
{
  task: "请给李四预订#{@city}的运动健身度假酒店...",
  city: @city,
  check_in_date: @check_in_date.to_s,
  guest_name: @expected_guest_name,
  facilities_required: '健身房、游泳池、运动设施'
}
```

**优化后（v234模式：requirements hash）**:
```ruby
{
  task: "李四6天后要去深圳进行健身训练，需要预订配备专业健身房和游泳池的酒店...",
  requirements: {
    beneficiary: '李四',
    city: @city,
    facilities_required: '专业健身房、游泳池、运动设施',  # 从"健身房" → "专业健身房"
    check_in_date: @check_in_date.to_s,
    check_out_date: @check_out_date.to_s,
    nights: (@check_out_date - @check_in_date).to_i,
    purpose: '健身训练'  # 新增：明确目的
  },
  hint: "在#{@city}筛选配备专业健身房和游泳池的酒店..."
}
```

**改进理由**: 
- 参考v234的requirements结构，将参数分组
- 任务描述更自然（"李四6天后要去...需要..."）
- 增加purpose字段明确目的（健身训练 vs 度假）
- 所有设施描述统一为"专业健身房"而非普通"健身房"

### 4. 断言注释增强（中文详细说明）

**优化后**: 每个断言都有详细的多行注释，并强调"专业健身房"

```ruby
# 断言3: 选择配备专业健身房的酒店（35分）- 核心业务逻辑
# 作用: 验证酒店是否配备专业健身房、游泳池等运动设施
# 验证逻辑:
#   - 检查 hotel.facilities 字段是否非空
#   - 使用正则匹配关键词: 健身|游泳池|泳池|运动
#   - 不区分大小写（/i 标志）
add_assertion "选择配备专业健身房的酒店（核心要求）", weight: 35 do
  # 检查是否有专业健身运动相关设施
  has_fitness = hotel.facilities.to_s.match?(/健身|游泳池|泳池|运动/i)
  expect(has_fitness).to be(true), 
    "酒店未配备专业健身运动设施。当前酒店: #{hotel.name}，设施: #{hotel.facilities}"
end
```
