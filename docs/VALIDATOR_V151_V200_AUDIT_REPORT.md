## 审查方法论

### 审查维度
1. **描述一致性**: description 是否准确反映任务要求
2. **simulate 实现**: simulate 是否按照 description 执行
3. **verify 断言**: verify 是否验证了 description 中的所有关键点
4. **权重分配**: 断言权重是否合理分布（总和=100）
5. **错误信息**: 错误提示是否清晰具体

### 核心模式与最佳实践

#### 1. Query Pattern（查询模式）

所有验证器都遵循正确的查询模式：
```ruby
all_records = Model
  .joins(:associations)
  .includes(:associations)
  .where(associations: { core_entity: @entity_value })  # 按核心实体过滤
  .where(data_version: @data_version)                    # 会话隔离
  .order(created_at: :desc)
  .to_a
```

**关键原则**:
- ✅ 始终包含`data_version`过滤（会话隔离）
- ✅ 按核心实体过滤（景点名、酒店名、航班号）
- ❌ 不在查询中过滤待验证属性（日期、价格、房型等）

#### 2. Assertion Structure（断言结构）

标准断言模式：
```ruby
def verify
  # 断言1: 存在性验证（20-25%）
  add_assertion "创建了订单" do
    all_records = query_with_data_version
    @orders = all_records.select { |o| meets_criteria? }
    expect(@orders).not_to be_empty
  end
  
  return if @orders.nil? || @orders.empty?  # Guard clause
  
  # 断言2-N: 属性验证（10-30%每个）
  add_assertion "属性A正确" do
    @orders.each { |o| expect(o.attribute_a).to eq(@expected_a) }
  end
end
```

#### 3. Weight Distribution（权重分配）

常见权重分配模式：
- **存在性+数量**: 20-25%
- **核心实体正确**: 10-15%
- **基础属性验证**: 10-15%每个
- **业务逻辑/优化**: 20-30%（最高权重）

所有验证器权重总和均为100%。

#### 4. Error Messages（错误消息）

优秀的错误消息模式：
```ruby
expect(order.visit_date).to eq(@visit_date),
  "游玩日期错误。期望: #{@visit_date}（后天）, 实际: #{order.visit_date}"
```

所有验证器的错误消息都包含：
- 期望值
- 实际值
- 上下文说明
