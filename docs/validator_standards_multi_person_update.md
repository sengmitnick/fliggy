# VALIDATOR_WRITING_STANDARDS.md 多人场景优化总结

## 📋 更新背景

原文档中的"家庭/多人场景"部分仅覆盖了**家庭门票模式**（父母+孩子），但实际业务场景更加丰富，包括：
- 朋友结伴出行（3-5人成人）
- 亲子游（妈妈/爸爸单独带孩子）
- 独立儿童（孩子自己购票）
- 大团体出游（5人以上混合）

本次更新将该部分扩展为更全面的**多人出行场景**指南。

---

## ✅ 主要更新内容

### 1. **章节标题优化**

**更新前：**
```
#### 家庭/多人场景（家庭门票模式）
```

**更新后：**
```
#### 多人出行场景
```

**原因：** 
- "家庭门票模式"过于狭窄，无法覆盖朋友、独立儿童等场景
- "多人出行场景"更具通用性，涵盖所有多人组合

---

### 2. **新增 5 种真实场景示例**

#### ✅ 场景1：家庭出游（父母+孩子）

**典型案例：** 张三一家三口（张三、王芳、小明）

**标题示例：**
- ✅ `给张三一家预订后天上海迪士尼门票（张三、王芳、小明，最便宜）`
- ✅ `给张三一家预订北京欢乐谷门票（2成人+1儿童，最便宜）`
- ❌ `预订迪士尼门票（2成人+1儿童）` ← 缺少受益人

**关键点：**
- 联系人：通常是父亲（张三）
- 订单分类：成人票订单 + 儿童票订单
- passenger_ids：`[@zhangsan.id, @wangfang.id]` + `[@xiaoming.id]`

---

#### ✅ 场景2：朋友结伴（3-5人成人出行）

**典型案例：** 张三、李四、王芳三人结伴游

**标题示例：**
- ✅ `给张三、李四、王芳预订明天长城门票（3人，最便宜）`
- ✅ `给张三和朋友预订后天环球影城门票（4人成人票）`
- ❌ `预订长城门票（3个成人）` ← 缺少具体姓名

**关键点：**
- 联系人：通常是第一位（张三）
- 订单分类：单个成人票订单，quantity=3
- passenger_ids：`[@zhangsan.id, @lisi.id, @wangfang.id]`

**与家庭场景的区别：**
- 家庭：需要分成人票/儿童票订单
- 朋友：全部成人，单个订单即可

---

#### ✅ 场景3：亲子游（妈妈+孩子）

**典型案例：** 王芳带小明去动物园

**标题示例：**
- ✅ `给王芳和小明预订明天动物园门票（1成人+1儿童）`
- ✅ `给王芳预订带小明去海洋馆的门票（最便宜）`
- ❌ `预订动物园亲子票` ← 不明确受益人

**关键点：**
- 联系人：母亲（王芳）
- 订单分类：成人票订单 + 儿童票订单
- passenger_ids：`[@wangfang.id]` + `[@xiaoming.id]`

**与家庭全员出游的区别：**
- 只有单亲+孩子，成人票 quantity=1
- 联系人是母亲而非父亲

---

#### ✅ 场景4：独立儿童（孩子自己出行）

**典型案例：** 小明独自买票进公园玩

**标题示例：**
- ✅ `给小明预订明天植物园儿童票（1张）`
- ✅ `帮小明买后天科技馆门票（儿童票）`
- ❌ `预订1张儿童票` ← 不明确受益人

**关键点：**
- 联系人：儿童本人（小明）
- 订单分类：仅儿童票订单
- passenger_ids：`[@xiaoming.id]`

**实际业务场景：**
- 家长放心孩子独立出行
- 孩子参加学校组织的活动
- 青少年独立游玩

---

#### ✅ 场景5：大团体（5人以上）

**典型案例：** 张三带全家+朋友共6人出游

**标题示例：**
- ✅ `给张三一家和朋友预订周末度假村门票（6人，最优惠）`
- ✅ `给张三预订公司团建活动门票（8人成人票）`

**关键点：**
- 联系人：组织者（张三）
- 订单分类：根据年龄自动分成人票/儿童票
- passenger_ids：动态计算，根据身份证号判断年龄

**代码要点：**
```ruby
adult_travelers = @travelers.select { |t| calculate_age(t.id_number) >= 18 }
child_travelers = @travelers.select { |t| calculate_age(t.id_number) < 18 }
```

### 3. **通用规则总结**

#### 标题格式规范

| 人数 | 标题格式 | 示例 |
|------|---------|------|
| 1人 | `给XX预订...` | `给张三预订明天酒店` |
| 2-3人 | `给XX、YY、ZZ预订...` | `给张三、李四、王芳预订长城门票` |
| 4人以上 | `给XX和朋友预订...` 或 `给XX一家预订...` | `给张三一家和朋友预订度假村门票（6人）` |

**原则：**
- ✅ 明确列出主要受益人姓名（2-3人时列全名，4人以上可简化）
- ✅ 保留人数描述有助于理解场景（如"3人"、"2成人+1儿童"）
- ❌ 纯抽象描述无具体姓名

---

#### prepare 查询规范

**所有多人场景的通用模式：**
```ruby
# 1. 查询所有出行人的 passenger 记录
user = User.find_by!(email: 'demo@travel01.com', data_version: 0)
@zhangsan = user.passengers.find_by!(name: '张三', data_version: 0)
@lisi = user.passengers.find_by!(name: '李四', data_version: 0)
# ...

# 2. 确定联系人（通常是第一位成人或家长）
@expected_contact_phone = @zhangsan.phone

# 3. 构建期望的游客姓名列表
@expected_passenger_names = [@zhangsan.name, @lisi.name, ...]
```

**❌ 禁止：**
- 在 simulate 中查询 `data_version: 0`
- 硬编码电话：`'13800138000'`
- 硬编码姓名：`'张三'`

---

#### simulate 创建规范

**关键字段：**
```ruby
TicketOrder.create!(
  ticket_id: xxx,
  contact_phone: @expected_contact_phone,  # ✅ 使用实例变量
  passenger_ids: [@zhangsan.id, @lisi.id],  # ✅ 关联所有游客
  quantity: 2,  # ✅ 与 passenger_ids 数量一致
  data_version: @data_version  # ✅ 会话隔离
)
```

**订单分类规则：**
- 全部成人：单个成人票订单
- 全部儿童：单个儿童票订单
- 成人+儿童：分别创建成人票和儿童票订单

---

#### verify 验证规范

**所有多人场景固定验证（合计 20 分）：**

**断言1：联系人信息正确（10分）**
```ruby
add_assertion "联系人信息正确（#{@expected_contact_phone}）", weight: 10 do
  [@adult_orders, @child_orders].flatten.each do |order|  # 或单个 @order
    expect(order.contact_phone).to eq(@expected_contact_phone),
      "联系人电话错误。期望: #{@expected_contact_phone}，实际: #{order.contact_phone}"
  end
end
```

**断言2：游客信息正确（10分）**
```ruby
add_assertion "游客信息正确（张三、李四、王芳）", weight: 10 do
  # 收集所有订单的 passenger_ids
  all_passenger_ids = (@adult_orders + @child_orders).flat_map { |o| o.passenger_ids || [] }.compact.uniq
  
  expect(all_passenger_ids).not_to be_empty,
    "订单中未关联任何游客信息（passenger_ids 为空）"
  
  # 查询关联的游客
  actual_passengers = Passenger.where(id: all_passenger_ids, data_version: 0)
  actual_names = actual_passengers.pluck(:name).sort
  
  expect(actual_names).to match_array(@expected_passenger_names.sort),
    "游客名单错误。期望: #{@expected_passenger_names.sort.join('、')}，实际: #{actual_names.join('、')}"
end
```

### 4. **检查清单更新**

**更新前：**
```markdown
- [ ] 家庭门票验证：联系人断言（10分）+ 游客信息断言（10分）= 合计20分
```

**更新后：**
```markdown
- [ ] 单人场景：乘客信息验证（姓名+电话，10分）
- [ ] 多人场景：联系人断言（10分）+ 游客信息断言（10分）= 合计20分
```

**原因：**
- 明确区分单人和多人场景的验证方式
- "多人场景"比"家庭门票"更具通用性

## 🎯 优化效果

### ✅ 文档更全面
- 从单一家庭场景扩展为 5 种真实场景
- 覆盖所有常见的多人出行组合

### ✅ 更贴近实际业务
- **朋友结伴**：覆盖成人团体出游
- **亲子游**：覆盖单亲带孩子场景

### ✅ 代码示例更详细
- 每个场景都有完整的 prepare/simulate/verify 代码
- 标注关键点和注意事项

- 提炼出所有多人场景的共同模式
- 明确 prepare、simulate、verify 的规范

## 📝 使用建议

### 编写新验证器时

1. **确定场景类型**
   - 单人 → 使用"单人场景"模式
   - 2-3人 → 根据关系选择对应场景（家庭/朋友/亲子）
   - 4人以上 → 使用"大团体"模式

2. **参考对应示例**
   - 复制场景代码模板
   - 根据实际需求调整人员组合

3. **验证标题格式**
   - 2-3人：列全名
   - 4人以上：简化描述

4. **确保验证完整**
   - 联系人断言（10分）
   - 游客信息断言（10分）
   - 合计 20 分
