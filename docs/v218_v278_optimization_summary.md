**优化前**:

**优化后**:
```ruby
# 验证用例278: 给张三囤万豪酒店套餐（2晚连住）
# 
# 任务描述:
#   帮张三囤购万豪酒店套餐（2晚连住通兑），先囤货后预约，有效期内随时使用。
#   Agent 需要搜索万豪酒店套餐，选择2晚连住套餐，使用囤货模式（stockup）购买。
# 
# 业务流程（5个关键步骤）：
#   1. 搜索万豪酒店品牌的酒店套餐产品
#   2. 筛选2晚及以上的套餐（night_count >= 2）
#   3. 确认用户余额充足（需要≥套餐价格）
#   4. 使用囤货模式（stockup）购买套餐（不需指定入住日期）
#   5. 填写联系人信息（张三）并提交订单
# 
# 复杂度分析（5个关键点）：
#   1. 需要理解品牌筛选：万豪酒店套餐（title LIKE '%万豪%'）
#   2. 需要理解套餐晚数：2晚连住（night_count >= 2）
#   3. 需要理解囤货模式：stockup（先购买后预约，不需指定入住日期和酒店）
#   4. 需要检查余额是否充足：user.balance >= package.price
#   5. 需要理解有效期：套餐购买后在有效期（valid_days）内可随时使用
#   ❌ 不能一次性提供：需要先搜索套餐→检查余额→囤货购买
# 
# 评分标准（4项，总计100分）：
#   1. 创建了酒店套餐购买订单（25分）
#   2. 购买的是指定酒店品牌套餐（万豪）（40分）- 核心业务逻辑
#   3. 支付金额正确（20分）
#   4. 订单状态正确（pending/confirmed/paid）（15分）
# 
# 使用方法:
#   rake validator:simulate_single[v278_redeem_hotel_stay_promotion_package_validator]
#   或访问 http://localhost:<PORT>/api/tasks 获取任务列表
```

## 优化标准

根据参考验证器总结的标准格式：

### 头部注释结构
```ruby
# 验证用例{编号}: {完整标题（包含受益人、业务对象、核心需求）}
# 
# 任务描述:
#   {详细的业务场景说明，2-3句话}
#   {Agent需要完成的核心任务}
# 
# 业务流程（N个关键步骤）：
#   {具体的操作步骤列表}
# 
# 复杂度分析（N个关键点）：
#   {技术难点和业务逻辑复杂点}
#   ❌ 不能一次性提供：{说明为什么需要分步骤}
# 
# 评分标准（N项，总计100分）：
#   {各项评分标准，标注核心业务逻辑}
# 
# 使用方法:
#   rake validator:simulate_single[validator_id]
#   或访问 http://localhost:<PORT>/api/tasks 获取任务列表
```

### Title/Description 标准
- Title应该完整描述任务，包含受益人（如"给张三"）
- Description可以是title的精简版或补充说明
- 两者应该保持语义一致

### 评分标准格式
- 明确标注分值（如"25分"而非"25%"）
- 总分必须为100分
- 标注核心业务逻辑项（如"- 核心业务逻辑"）
